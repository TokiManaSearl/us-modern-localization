# 通读、锁定与分批执行

## 1. 接收原文，建立阅读覆盖

确认书名或工作代号、上传文件的顺序、章节数量、是否完本、缺章及重复章。没有作品名可用中性工作代号，不据此编造书名或设定。未上传原文时只请求原文，不生成假映射。

- DOCX 按 [运行环境](../runtime.md) 使用现有文档工具或 python-docx 读取段落、表格及有关脚注等内容；不支持的内容明确标出；TXT/MD 用文本工具分段读。其他格式只用当前实际具备的读取能力；不能读取的内容须说明并请求可读版本，不能当作空白略过。
- 以原章节为单位，建立章号、原题、文件位置、阅读起止与完成状态。无章节时按场景/自然段建立稳定编号，并在计划中说明，不擅自重排。
- 通读本次全部材料，长书分批读，保存紧凑证据记录；上一批摘要只帮助定位，不能替代下一批原文或需要复核的原段。
- 每章记录事件顺序、角色动机与选择、主支线与感情关系变化、人物/读者各自所知、伏笔埋设与回收、重要物件、时间地点以及文化依赖。未揭示真相写“尚未揭示”，不推断成事实。
- 原文版本变化时，标记受影响阅读与映射记录失效，重新核对，不把旧版与新版拼接使用。

## 2. 建立两份内部底账

可以用 Markdown 表或 UTF-8 JSON 保存，内部记录不是面向用户的交付文件。

### 剧情保护清单

每项至少含：事件编号、原章/场景及定位引文、参与角色标识、动机、起因→行动→结果、感情/关系变化、人物与读者的知情边界、伏笔关联、必须保留的戏剧功能、改写定位、核对状态。

有的场景只有照料、等待或情绪变化，也要保留，不能以“没有冲突”为由删去。文化细节若是误会、证据、双关、身份揭示的条件，必须列为保护项，而非装饰物。

### 全局映射台账

按 mapping.md 建立实体、别名、规则与专业内容的映射；区分“候选、锁定、待解决、已撤销”。原文事实、执行者提案和已采用方案分别标明，不混写。

## 3. 拟定新书名，先交计划后锁定

通读后，根据固定的现代美国都市背景、核心冲突、主要关系或关键意象，重新拟定一个中文书名。接收时记录的原书名/工作代号只用于来源定位，不直接沿用为成稿标题。

- 新书名须简短、直白、易懂、便于人工回译，避免长句式剧情简介、生僻词、中国成语典故和依赖汉字的双关。
- 契合转置后的现代美国都市故事及北美读者可理解的文化背景；即使原作为古代或仙侠，新标题也按已锁定的现代人物、关系和冲突拟定，不沿用古代爵号、修炼等级或神话身份作题名。
- 不照抄原中文标题，不仅替换其中的人名地名，也不以添加“美国版”“海外版”等后缀充当重新命名。
- 标题传达的关系、冲突或意象必须在故事中真实存在；不夸大题材，不提前泄露核心反转，不为了标题新增或改写剧情。
- 在《映射计划表》“本次范围与目标世界”中记录“来源原标题→拟定新书名”，附一句命名理由和采用状态。原题只用于来源追溯，不作为成稿副标题。新书名随映射计划一起确认，无需为起名另增一次确认或一个交付文件；已获自动执行授权时可由执行者选择并注明依据，不冒充用户确认。
- 锁定后，两份 Word 的文件名、封面、页眉及其他书名引用统一使用新书名。成稿复审时再核对题名与实际内容是否相符；若需更名，同步更新两份文档并记录版本，来源文件和已建立的内部记录目录不因改名随意移动。

全量通读与初步因果核对完成后，按 docx-delivery.md 生成并交付《书名_映射计划表.docx》。这一份里含目标时代与地区基线、剧情保护、全局文化依赖清单、锁定映射台账、专业内容处理、风险及待决定事项，逐章变更对照随改写进展补进同一份。

默认等待用户确认计划后才写正文。此前已明确授权自动执行的，可以交付计划后继续；只有用户明确授权自主选择时才由执行者决定，并注明“执行者采用”；无人回复不等于确认，不假设宿主具备自动代答能力。不得借自动执行授权改动核心剧情、感情线或反转。

锁定记录保存计划版本、锁定依据、目标世界规则和映射表。后续出现遗漏实体先查全书别名与关系，不先凭当前章临时命名。

## 4. 不能同时满足时怎样处理

以下任一情况标为高风险：关键身份依赖宗族/嫡庶或科举制度；反转靠汉字拆字、谐音、成语谜底；救治或证据链依赖特有医疗观念；神话规则、祖先祭祀或法律身份无法在目标世界保持相同结果。题材标签本身不是不能转置的证明，必须定位具体机制。

在计划及所有包含有关范围的改写 Word 第一部分醒目写：

**文化转置风险警告：本书部分核心剧情依赖原文化机制，尚不能在不改变核心剧情的前提下完成等效转置。**

紧随警告写：相关章节、来源定位、依赖机制、替换后哪条因果不成立、可选处理及各自代价、尚需人工决定的事项。源文化名称仅在“来源”栏保留。

优先提出不改变结果和动机、且符合现代美国都市现实的载体；若做不到，暂停受影响剧情链，列出最小现实化改动及其影响，询问是否授权该项核心改编。目标背景不再作为选项，不建议退回中世纪或奇幻世界；未获授权的部分保留为待解决，不伪称已完成。原有禁止改剧情约束未被明确改变前，不新增证人、超能力、亲属身份或法律特权来补洞。可继续互不依赖的已锁定章节，但交付标为“部分完成/待复审”，不得用占位符冒充完整正文。警告保留至问题确已解决；仅有免责声明不是解决。

## 5. 逐章改写，默认五章一批

每章开始前读取原章全文、相关上下文、锁定映射、保护清单及上一批连续性记录。按原章顺序、场景顺序与叙事视角改写完整正文；不合并或删掉支线、不压缩成梗概、不用新增戏剧冲突代替原场景。

每章完成后对照原章核对：事件、参与者、动机、选择、结果、证据作用、关系变化、信息揭示与情绪兑现。逐项补进《映射计划表》里该章的对照条目，不能先改完再凭记忆概括。

每五章及全书末尾核对跨章关系、命名、地点距离、时序、货币与数量尺度、职业权限、能力限制、伤病后果、伏笔回收。五章是默认检查节点，不是交付截断上限；很长的单章可按完整场景拆工作批，但最终还原一个章节。

每五章同时跑一次残留 QA 校验（见 qa-review.md）：先跑扫描器标记，再对照映射台账反查未替换的来源名称，逐条判定后修正本批。全书交付前扫整份。扫描不通过就继续修，不进入下一批。**不得**为让扫描归零而删剧情、改动机或删掉必要的文化描写；确需保留的登记白名单并写明依据。

每批保存已读/已改/已审范围、计划版本、未解决风险、下一步。续接时按这些文件恢复，不凭聊天印象。

## 6. 锁定映射发生变化

先查旧译名、别名、间接称谓、相关关系及规则在全书中的使用点，形成影响清单。实体改名不改变实体编号；语义改变必须回查动机与因果。更新映射版本并同步此前正文与《映射计划表》里的台账和逐章对照，再继续后文；不得新旧映射并存。姓名变化不等于授权变更身份。

最终复审依据原文和两份底账完成，具体交付检查见 docx-delivery.md。
