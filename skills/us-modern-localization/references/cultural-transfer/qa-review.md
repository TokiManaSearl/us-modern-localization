# 残留文化依赖 QA 校验

改写稿交付前的独立校验环节。方法改编自 scriveno 3.8.0 的 `cultural-adaptation` 评审（MIT License, Copyright (c) 2026 Scriveno contributors），按其“分类扫描 + 分级 + 逐条给定位与建议”的结构，改为检查**中文改写稿里是否残留源文化设定**，而不是检查译文对目标语言的本地化程度。

本环节只做标记与判定，不改写正文；命中的修改回到 process.md 的改写流程执行。

## 现代美国都市一致性检查（每批与全书必做）

除源文化残留，还须通读检查目标是否始终是现代美国都市现实背景。当前脚本主要定位中国词条，不覆盖全部时代错配，以下检查由执行者逐场完成，不声称脚本已自动验证。

- 城市、都市圈、住所、工作场所与出行耗时能对齐；不能美国地名下仍运行封建领地、王室继承或宗门法权。
- 职业身份、执法司法、医疗保险、教育、财产和雇佣权限符合现代美国常识；不能企业负责人同时有领主式审判权。
- 通信、交通、监控与记录条件前后一致；失联、取证、救援不能无理由忽略已存在的现代设施。
- 仙术、灵丹、血统魔法、复活、穿越等不得作为现实成立的解法；检查其已锁定的现实替代是否有依据、代价与限制。不可把“西式魔法名”判为已现代化。
- 历史/宗教/影视谈论、展品和比喻不等于时代错配，按语境判定；但不得借回忆或戏中戏保留未转置的主要剧情线。发现机制层混搭按 high 处理，回查映射并修复，核心事件需改动则先按 process.md 请求授权。

## 为什么需要独立一遍

改写时按场景逐章判断，容易在跨章、配角、过场台词、章名、环境描写里漏掉制度名词。人眼复读会顺着语义补全，读不出“居委会”出现在美国公寓里。所以要分开做：先扫描标记，再逐条判断。

两层扫描都要做，缺一不可：

1. **确定性扫描**：`scripts/scan-cultural-residue.js`，用词表抓制度类残留，给出行列定位。
2. **台账扫描**：用同一脚本加 `--ledger` 读锁定映射台账，核对每个来源名称是否还出现在目标正文里。姓名、地名、方言这类无法靠通用词表覆盖的，靠这一层兜住。

脚本零命中**不能**证明没有残留。它抓不到“换了机构名但流程还是中式”的情况，也抓不到文化喻体、亲属礼序、求医方式。通读判断仍要做。

## 扫描类别与默认严重度

在 scriveno 原有类别上加中国制度专项，两者合并使用。

| 类别 | 默认严重度 | 抓什么 | 典型残留 |
|---|---|---|---|
| `institution` | high | 行政、社区、单位、治安机构 | 居委会、村委会、街道办、派出所、公安局、单位、街道 |
| `document` | high | 身份、户籍、档案类证件 | 户口本、户口、户籍、身份证、档案、粮油关系 |
| `emergency_number` | high | 中国急救/报警短号 | 110、119、120、122、114 |
| `medical_system` | high | 医疗体制与分级 | 三甲、二甲、挂号、医保、社保、新农合、社区卫生服务中心、乡镇卫生院 |
| `legal_system` | high | 司法与行政救济 | 检察院、政法委、劳动教养、信访、人民调解、行政复议 |
| `education_system` | high | 升学与校内职务 | 高考、中考、班主任、年级主任、教导主任、重点中学、学区房、保送 |
| `money_unit` | high | 货币与中式计量 | 人民币、元/块（金额语境）、斤、两、里、亩、寸、尺、丈 |
| `title_address` | medium | 称谓与敬语体系 | 师傅、同志、领导、科长、处长、局长、书记、主任、大爷、大娘 |
| `idiom` | high | 成语、典故、诗词、歇后语 | 对应 scriveno `idiom`；依赖中国文学知识的比喻与四字格典故 |
| `humor` | high | 谐音、拆字、方言梗 | 对应 `humor`；双关若承担证据作用，先按核心风险处理 |
| `custom` | medium | 节庆、礼俗、婚丧、人情往来 | 春节、中秋、元宵、端午、清明、随礼、红包、拜年、饭局、单位分房 |
| `food` | low | 饮食指向过强时 | 对应 `food`；家常菜不必改，出国名菜、地方小吃、药膳等带文化标识的才标 |
| `name_order` | medium | 姓在前与称谓组合 | 对应 `name_order`；张先生、李嫂、老王、小陈 |
| `politeness` | medium | 中式客套与尊卑语域 | 对应 `politeness`；您慢走、吃过没有、劳您费心、不好意思打扰了 |
| `punctuation` | low | 标点体系残留 | 对应 `punctuation`；中文引号与省略号本身不算问题，混入英文标点或全角半角错乱才标 |
| `measurement` | medium | 非中式但来源文化遗留的单位混用 | 对应 `measurement`：改写后混用公制与英制、或保留了原作的公里/公斤而未统一 |

严重度调整：会让读者出戏、暴露设定错乱、或让机构职能说不通的，一律升到 high；纯风格偏好降到 low；其余保持默认。

## 逐条判定格式

每条命中写清下面几项，便于人工复审；对照表里同章条目与之对应。

```text
类别：{category}
严重度：high / medium / low
定位：第 N 章《章名》第 X 段（或 文件:行:列）
命中原文：{摘录，不超过 40 字}
问题：{为什么在这里读起来不对：机构不对、流程不对、与已锁定映射冲突、时代错配}
处置：已改 / 待改 / 保留（说明理由）
建议：{回查台账该实体应写成什么；台账里没有就先补登记}
```

判定时容易误判的三类，先确认再定级：

- **同形不同义**：如“主任”在医生语境可指 department head，属正常；“居委会主任”才是残留。
- **合理保留**：已锁定的目标姓名礼貌称呼、现代场景中的历史谈论等须按具体位置判断。原作中国回忆线仍须转置，不能仅因“回忆”就自动放行；核心机制无法等效时按风险流程处理。
- **计量换算**：改写已统一为英制时，残留公制数字要换算，不能只删单位。

## 台账扫描

改写前把锁定映射台账存成 JSON 供本环节使用，最少包含来源名称与锁定目标：

```json
{
  "entities": [
    { "id": "E001", "source": ["张建国", "老张"], "target": "丹尼尔·海尔", "category": "name" },
    { "id": "E014", "source": ["城西派出所"], "target": "第十四警区", "category": "institution" }
  ]
}
```

扫描时逐个来源名称在目标正文里检索，命中即为残留，严重度按实体类别取上表默认值。台账里的 `target` 也会被反向自检：若同一目标名出现在两个实体上，报映射冲突，先解决再继续。

JSON 用无 BOM 的 UTF-8 写入，用当前文件工具或 Python `encoding='utf-8'`。具体扫描命令、DOCX提取及脚本局限见 [运行环境](../runtime.md)。退出码0不代表台账无冲突，必须同时检查 `conflicts`。

## 何时跑

- 每批五章的连续性核对时跑一次，扫本批范围。
- 全书交付前扫整份。
- 修改映射或补改某章后复扫受影响范围，不重跑全书。

有问题先修，修完复扫；同一范围最多三轮，仍有未清项列入报告并说明原因。**不得**为了让扫描归零而删除剧情、改掉人物动机或删掉必要的回忆段落；确实需要保留的登记进白名单并写明理由。

## 合理保留记录

每条保留记录写章节/段落位置、命中文本、语义判定理由及授权依据；例如“第二章第5段｜沃德女士｜锁定目标姓名的正常礼貌称呼｜按台账复核”。不把同一词在全书所有位置自动放行，不把未转置的中国回忆线登记成例外以回避现代都市目标。

当前脚本白名单会全局抑制文本及相邻片段命中，因此默认不传 `--whitelist`；在未过滤的扫描报告中逐项人工处置并保留复扫记录。它不改变映射台账，不得为了让数字归零删除剧情或掩盖漏改。

## 结果怎样进入交付

- 扫描结果、白名单、复扫记录保存在 `工作记录/文化转置/{书名}/`，不列为用户交付文件。
- 未解决的 high 项计入交付报告，并在《映射计划表》与改写正文开头的风险页对应位置说明；不能默认为已解决。
- 《映射计划表》的逐章变更对照要能对上本环节的每条命中：已改的写进逐章变更，保留的写进处置列并注明依据。
