# Codex 运行环境

## 安装与执行是两件事

安装只复制技能文本、参考与扫描脚本，不安装Codex、Python、Node或Word库，不上传小说，不调用模型API。实际创作由用户当前Codex会话执行，需要其已有模型访问权限。

- 文件读写/搜索：使用当前Codex实际暴露的工具或终端；不调用其他工作台的专属工具名。修改前读取，来源只读，产物另存。
- 提问：使用当前可用提问能力；不能假设有超时自动回复。没有回复不是授权。
- 脚本：Node.js 20+运行残留扫描器（仅标准库）；Python 3.10+与python-docx用于Word。优先宿主已配置的解释器；在普通Codex中使用用户环境已有的python/python3或Windows py启动器。缺失时说明并请用户准备，不自动下载或安装。
- 文档：若宿主提供文档技能先使用；否则用python-docx读取、新建和重开。它可能不暴露全部脚注、文本框等内容，不得静默丢弃源文。目录与书签方法见 [交付规范](cultural-transfer/docx-delivery.md)。

初次执行可让终端验证 `node --version` 与 `python -c "import docx; print(docx.__version__)"`（将python替换为已配置解释器）。库缺失就报告真实错误，不声称技能安装顺便提供了这些依赖。

## 路径

`<skill-dir>` 是本文件上一级目录，即含SKILL.md的安装目录。不能把用户书稿保存到这个目录。用户原文、工作记录与交付一律留在当前写作项目。

```text
node "<skill-dir>/references/cultural-transfer/scripts/scan-cultural-residue.js" "<项目>/.localization-work/正文.txt" --ledger "<项目>/工作记录/文化转置/<书名>/mapping.json" --json --out "<项目>/.localization-work/qa.json"
```

扫描器仅接受UTF-8文本，不要把DOCX二进制直接传给它。先从最终DOCX提取章节正文到临时TXT（不混入计划表来源字段），保存段落/章节对应关系，再扫描；检查结果要映射回原DOCX章节。临时文件不对用户交付。

当前扫描器是定位辅助，不是完整审查器：有词条误报；每词默认最多20处；必须分章扫描并用文本搜索补齐全部出现点。不要把筛选后的少量输出当完整覆盖。其白名单为全局文本抑制，可能隐藏相邻命中，因此本发布版默认不传 `--whitelist`，保留完整扫描结果，在工作记录逐条按位置判定保留理由。台账冲突须单独查看 `conflicts`，不能仅凭退出码认定无冲突。参数/读取失败、无有效扫描文件不得当作零残留通过。

计划表例外不放行整条源世界剧情：若原文有中国回忆或古代主线，也按现代美国都市目标处理；真正不能等效的核心机制按流程请求授权。宗教或历史谈论中的非事实机制按语境判断。

## Word 验收

从保存后的DOCX重开核对完整章数、标题、正文与计划表条目，再专项检查本次生成的目录域、书签及内部链接是否一致。结构检查不是视觉检查；没有已授权可用的预览工具时报告未检查分页，提醒用户在WPS更新目录并核对版式。不得用PDF、MD冒充要求的DOCX。

用户要求依赖配置时，提供适合其环境的操作建议并等待其授权；本技能安装器永不执行依赖安装。操作Word时不依赖Microsoft Word进程或特定本机绝对路径。
